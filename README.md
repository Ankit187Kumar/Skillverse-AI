# SkillVerse AI

**Learn. Practice. Evolve.**

SkillVerse AI is an all-in-one self-development platform: AI mock interviews (text or voice), personalised learning paths, a research agent that cites its sources, a sandboxed coding lab, and progress analytics that tie it all together. It is a responsive web app, so it runs in modern browsers on Android phones and tablets, Windows and macOS.

All five roadmap phases are implemented in this repository.

## Features

### Phase 1 — Interviews, dashboard, accounts
- Sign-up/login (bcrypt, httpOnly signed session cookie, CSRF header check, rate limits), profile, resumes, settings, data export and account deletion.
- **AI Interviewer:** Technical, HR, Behavioral, Personality, Domain-Specific or Custom; role, skills, level, difficulty, duration, language, topics, goals, optional resume. Follow-up questions based on your answers.
- **Interview room:** explicit camera/mic consent, live camera preview (never recorded), mic level meter, timer, progress, live transcript, pause/end, clear status indicators.
- **Feedback report:** five criteria with explained weights, strengths, weaknesses, per-question feedback with suggested answers, tips, lessons, practice questions, skill gaps. "Confidence" is judged only from your wording, never from face, voice or emotions.
- **Resume analysis** (PDF/DOCX): skills, experience, education and projects feed personalised questions.

### Phase 2 — AI Learning Assistant
- A course for **any topic**: modules → lessons, learning objectives, outcomes and a capstone project, tailored to your level, goal and weekly time.
- Lessons with explanations, worked examples, key takeaways, **exercises with hints before solutions** (the full solution unlocks only after a hint or an attempt), and AI feedback on your attempts.
- **Quizzes graded on the server** (answers never reach the browser before you submit). Passing completes the lesson.
- **Adaptive:** low scores trigger review recommendations and a "simpler explanation" with analogies; a final assessment shows per-module scores and flags weak modules; strong mastery suggests a matching mock interview.
- Resume where you stopped, mastery tracking, AI-reviewed capstone projects.

### Phase 3 — AI Research Agent
- Research prompt + goals + field → an editable **research plan** (sub-questions and search queries).
- **Web search** via SearXNG (self-hosted, free), Brave or Tavily. Pages are downloaded and read, protected by SSRF checks.
- **Document library:** upload PDF, DOCX, TXT or Markdown. Text is chunked and embedded; you can search it semantically, with keyword (BM25) fallback.
- Structured reports with an executive summary, sections, key findings, compared viewpoints, limitations and open questions.
- **Citation integrity:** the model may only cite numbered sources the agent actually retrieved. Invalid citations are removed automatically, and "facts" without a valid source are relabelled as *unsupported* interpretations. Each source shows whether the agent actually read it or only saw a search snippet, plus the exact passages used.
- Save, copy, download as Markdown, print to PDF.

### Phase 4 — Coding Practice Lab
- 21 problems across Easy/Medium/Hard and 11 topics, with **152 test cases** (samples + hidden edge cases + large inputs that catch slow solutions). Every expected output is generated by a reference solution, and the small cases were cross-checked against brute-force solutions.
- CodeMirror editor with syntax highlighting (Python, JavaScript, Java, C++), auto-saved drafts, custom input runs.
- Code runs **only in an isolated sandbox** (Piston or Judge0), never on the app server. Verdicts: accepted, wrong answer, runtime/compile error, time/memory limit. Hidden test inputs stay hidden.
- Progressive hints → editorial; **AI review** of time/space complexity and mistakes (with hints to fix them, not full solutions); practice history and stats.

### Phase 5 — Voice, analytics, recommendations, deployment
- **Voice interviews:** questions read aloud, and answers spoken via the browser's speech recognition or a server STT (any OpenAI-compatible `/audio/transcriptions`, e.g. self-hosted faster-whisper). You review and edit the transcript before sending. Recording runs only while you press Record, and audio is never stored.
- **Progress & analytics:** overall progress, streaks and a 12-week activity heatmap, daily and weekly goals (editable), interview trends and per-type averages, skill-wise mastery across interviews, courses and coding, weaknesses and skill gaps, courses and projects, coding stats, 14 badges.
- **Personalised recommendations** linking modules together (e.g. an interview skill gap → "Start a course on X"; strong course mastery → "Interview on X"; a timed-out topic → the next problem in that topic), plus an **AI improvement roadmap** with focus areas, a weekly plan and milestones.
- **Production:** Dockerfiles, docker-compose (PostgreSQL, Caddy HTTPS, optional Ollama/Piston/SearXNG/Speaches), CI workflow, security test suite, `SECURITY.md`.

## What's real, and what depends on your setup

Everything above is implemented and calls real services. There is no hard-coded AI output. Some features need a service you choose to run:

| Feature | Needs | Without it |
|---|---|---|
| All AI features | Ollama (free, local) **or** an OpenAI-compatible API key | A banner explains the model isn't reachable; AI actions show clear errors |
| Semantic document search | An embedding model (`ollama pull nomic-embed-text`) | Falls back to keyword search automatically |
| Research web search | SearXNG (free, self-hosted), Brave or Tavily | Research uses your documents only, or is labelled "unverified general knowledge" |
| Running code | Piston or Judge0 sandbox (free, self-hosted) | Run/Submit are disabled; AI review still works and is labelled "not executed" |
| Voice answers | Chrome/Edge/Safari speech recognition, **or** an STT server | Text answers |
| Camera/mic | HTTPS (or `localhost`) | Text-only mode with an explanation |

**How this was verified:** 60 backend tests, TypeScript type-checking, ESLint and a production build all pass. A scripted browser run covered every module end to end: a voice interview with server transcription, a full course (lesson, hints, quiz fail → simpler explanation → pass, assessment, project), research with web search plus an uploaded document, coding (a brute-force solution timing out in the sandbox, then an accepted fast one), analytics and the AI roadmap, in light and dark mode at desktop and phone sizes. The model, search engine, sandbox and STT in that run were **stand-ins speaking the real HTTP protocols**, because they couldn't be downloaded in the build environment. Answer quality with your chosen model and the Docker images themselves still need a run on your machine.

## Architecture

```
Browser ─► Next.js (3000) ─/api/* proxy─► FastAPI (8000) ─┬─► Ollama / OpenAI-compatible LLM + embeddings
                                                          ├─► SearXNG / Brave / Tavily      (research)
                                                          ├─► Piston / Judge0 sandbox       (coding)
                                                          ├─► STT / TTS server (optional)   (voice)
                                                          └─► SQLite (dev) / PostgreSQL (prod)
```

- The browser only talks to Next.js; `/api/*` is proxied to FastAPI, so the session cookie is first-party.
- Long AI tasks (course outlines, lessons, research runs, roadmaps, project reviews) run as **background jobs** with progress the UI polls, so nothing times out and you can leave the page.
- One `LLMProvider` interface (`backend/app/services/llm.py`) with structured-output validation and an automatic repair retry.

```
backend/app/
  main.py, config.py, database.py, security.py, deps.py
  models.py (+ models_learning / models_research / models_coding / models_platform)
  routers/   auth users resumes interviews dashboard learning documents research coding voice analytics jobs
  services/  llm prompts interview_service learning research web retrieval documents coding runner analytics jobs activity
  data/problems.json.gz          # coding problem bank (built by scripts/build_problems.py)
backend/migrations/              # Alembic: 0001 initial, 0002 phases 2–5
backend/tests/                   # 60 tests incl. security matrix
frontend/src/app/(app)/          # dashboard interview learn research coding progress profile settings
frontend/src/components/         # app shell, charts, quiz, code editor, markdown, job status, ui/*
frontend/src/lib/                # api client, auth, theme, media, voice, job polling, types
deploy/, docker-compose.yml, .github/workflows/ci.yml
```

## Local setup

**Prerequisites:** Python 3.11+, Node.js 20.9+, and [Ollama](https://ollama.com/download) (or an API key for a hosted model).

```bash
# 1. Models (Ollama)
ollama pull llama3.2:3b          # chat model — see "Choosing a model"
ollama pull nomic-embed-text     # embeddings for document search

# 2. Backend
cd backend
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
cp .env.example .env                                    # Windows: copy .env.example .env
alembic upgrade head
uvicorn app.main:app --reload --port 8000               # API docs: http://localhost:8000/api/docs

# 3. Frontend (new terminal)
cd frontend
npm install
npm run dev                                             # http://localhost:3000
```

The coding problem bank loads automatically at startup. Camera and microphone need HTTPS or `localhost`. To test on a phone, use an HTTPS tunnel (e.g. `cloudflared tunnel --url http://localhost:3000`) or deploy.

## Optional services

Each needs only Docker and one line of config in `backend/.env`.

**Web search (Research Agent), free and self-hosted:**
```bash
docker run -d -p 8888:8080 -v "$PWD/deploy/searxng/settings.yml:/etc/searxng/settings.yml:ro" searxng/searxng
# backend/.env:  SEARCH_PROVIDER=searxng   SEARXNG_URL=http://localhost:8888
```
Or use `SEARCH_PROVIDER=brave` with `BRAVE_API_KEY`, or `tavily` with `TAVILY_API_KEY` (both have free tiers with monthly limits).

**Code sandbox (Coding Lab):**
```bash
docker run -d --privileged -p 2000:2000 -v piston-packages:/piston/packages ghcr.io/engineer-man/piston
python backend/scripts/piston_setup.py http://localhost:2000     # installs Python, Node, Java, GCC
# backend/.env:  CODE_RUNNER=piston   PISTON_URL=http://localhost:2000
```
Judge0 also works (`CODE_RUNNER=judge0`, `JUDGE0_URL`, optional `JUDGE0_API_KEY`). Piston needs `--privileged` to create its own per-run isolation; run it on a host you control, not exposed to the internet.

**Voice:** by default `STT_PROVIDER=browser` uses the browser's speech recognition (Chrome/Edge send audio to their vendor's cloud; Firefox doesn't support it). For private, server-side transcription run an OpenAI-compatible STT server such as [Speaches](https://github.com/speaches-ai/speaches) and set `STT_PROVIDER=openai_compatible`, `STT_BASE_URL=http://localhost:8001/v1`. Questions are read with the browser's voices unless `TTS_PROVIDER=openai_compatible`.

## Choosing a model

| Your machine | Chat model | Notes |
|---|---|---|
| 8 GB RAM, no GPU | `llama3.2:3b` (default) | Works; lessons and reports are simpler and can take 30–120 s on CPU. |
| 16 GB RAM or 8 GB GPU | `qwen3:8b` or `llama3.1:8b` | Recommended: noticeably better lessons, research and reviews. |
| 32 GB RAM or 12–16 GB GPU | `gemma3:12b` or `qwen3:14b` | Best local quality of these. |

Set `OLLAMA_MODEL` and pull it. Long transcripts and research need context: keep `OLLAMA_NUM_CTX=8192` or higher, and raise `RESEARCH_CONTEXT_CHARS` for large-context models. Check <https://ollama.com/library> for newer models; any chat model that can return JSON works.

**Hosted instead:** `LLM_PROVIDER=openai_compatible`, `OPENAI_BASE_URL`, `OPENAI_API_KEY`, `OPENAI_MODEL` (and `EMBEDDING_MODEL=text-embedding-3-small` for OpenAI). Keys stay on the server.

## Configuration

All settings are environment variables; [`backend/.env.example`](backend/.env.example) documents every one. Key production settings: `ENVIRONMENT=production`, a random 32+ character `JWT_SECRET`, `COOKIE_SECURE=true` (the app refuses to start without them), a PostgreSQL `DATABASE_URL`, and `ALLOW_PRIVATE_FETCH=false`.

## Tests and quality checks

```bash
cd backend
pytest                                   # 60 tests (fake model and sandbox; no services needed)
alembic upgrade head && alembic check    # migrations match the models
pip-audit -r requirements.txt            # dependency CVEs
bandit -q -r app -ll                     # static security scan

cd frontend
npx tsc --noEmit && npm run lint && npm run build
npm audit --omit=dev
```

The suite covers auth, sessions, CSRF, rate limits, the interview flow and failure recovery, learning (answer secrecy, hints-before-solutions, grading, adaptivity, assessment, projects), research (SSRF blocking, citation validation, unread-source labelling, no-source honesty), coding (verdicts, hidden tests, sandbox adapter parsing, static review), voice, analytics and goals. There is also a **security matrix** that walks every API route: all require sign-in, and no route returns another user's data. CI runs all of this ([`.github/workflows/ci.yml`](.github/workflows/ci.yml)).

At delivery: all tests pass, `bandit` reports no medium/high issues, and `pip-audit` and `npm audit` report no known vulnerabilities.

## Deployment

```bash
cp .env.production.example .env          # set DOMAIN, POSTGRES_PASSWORD, JWT_SECRET, model settings
docker compose --profile sandbox --profile search up -d --build
docker compose exec backend python scripts/piston_setup.py http://piston:2000
```
Caddy obtains HTTPS certificates automatically. Add `--profile local-ai` for an Ollama container (GPU strongly recommended) and `--profile voice` for Speaches. Full guide, sizing and backups: [`docs/DEPLOYMENT.md`](docs/DEPLOYMENT.md).

## Privacy and security

- Camera/mic are off until you turn them on; indicators show when they're active; the camera is never recorded or analysed; audio for transcription is discarded after the request.
- Resumes and documents: only extracted text is kept, never the original file.
- Per-user authorisation on every record, CSRF protection, security headers, rate limits, upload type/size/zip-bomb checks, SSRF-safe fetching, model output rendered as safe Markdown (no raw HTML), and user code isolated in a separate sandbox.
- Users can export all their data as JSON and delete their account (cascading to every table).

Details and the production checklist: [`SECURITY.md`](SECURITY.md).

## Costs and limits

- **Free paths:** Ollama, SearXNG, Piston/Judge0, browser speech, and SQLite/PostgreSQL are all free and open source. You pay only for hardware or hosting.
- **Hosting:** a small VPS (2 vCPU / 4 GB, roughly US$5–20/month) runs the app, database, SearXNG and Piston. Running 7B+ models well needs a GPU server, which costs much more than a hosted API at low volume.
- **Paid options:** hosted LLM APIs (per-token), Brave/Tavily search beyond free tiers, hosted Judge0, hosted STT/TTS. Check current pricing with the provider.

## Known limitations

- AI content (lessons, reviews, reports) can be wrong; the UI says so, research claims link to their passages, and test results, not the AI, decide coding verdicts.
- Research reads HTML and plain-text pages; PDFs found on the web aren't downloaded (upload them to the library instead). Sites that block bots appear as "snippet only".
- Scanned (image-only) PDFs aren't supported (no OCR).
- The rate limiter and job runner are in-process. For several API instances, move them to Redis or a queue (RQ/Celery); the interfaces are isolated for this.
- Browser speech recognition quality and language support vary by browser; server STT is more consistent.
- No email verification or password reset by email yet (needs an email provider).
